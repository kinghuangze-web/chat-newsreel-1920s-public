# 1920s 群聊新闻片

用户大概率只说一句「给我做一期」。剩下全是你的事。下面写的是你要做的判断、必须问用户的节点、照抄就能用的参数。

## 交付物

一个 `<name>.mp4`（1280×720，60–90 秒，有声）+ 一个 `DELIVERY.md`。

成功标准只有四条，全过才算完：

| 检查 | 命令 | 通过 |
|---|---|---|
| 引语命中 | `python tools/check_quotes.py work/chat.txt` | `ALL FOUND` |
| 读字时长 | `node core/render/readcheck.mjs "$(cygpath -w <项目>)"` | 0 项 BAD，退出码 0 |
| 时间线 | `python tools/timeline.py` | 末尾 `OK`，无 OVERLAP / SPILL / LONG |
| 联系表 | 人眼看 `stills/_sheet.jpg` | 无切字、无空画面、无出片门 |

判定细节：

- **读字时长** = `(汉字数 ÷ 4.5) + (其他字符 ÷ 15) + 1.5` 秒，从字完整进入画面起算
- **响度** `mux.sh` 自测，目标 −14 LUFS、真峰 ≤ −1 dB；人声段落要比纯配乐段落高 8 dB 以上
- **联系表**只看得清构图，可疑的单张打开原尺寸看
- **成片抽帧**必做一次。胶片颗粒在合成阶段叠，可能让细节更难读，静帧里看不出的问题这里能看出来

不合格怎么处理：

| 级别 | 例子 | 处理 |
|---|---|---|
| 阻断 | 引语对不上、数字没出处 | 必须改，不能交付 |
| 严重 | 字被切、空画面、旁白粘连 | 必须改，重渲染 |
| 一般 | 构图偏、比例不协调 | 写进 `DELIVERY.md`，下期改 |
| 提示 | 音色不够厚 | 写进 `DELIVERY.md`，不算缺陷 |

交付目录：

```
out/
├── <name>.mp4          交付用，1280×720
├── <name>-full.mp4     母版，1920×1080
├── DELIVERY.md
├── qc/                 抽帧
└── _raw/               无声画面 + mix.wav，不进交付层
```

`DELIVERY.md` 至少写六项：素材来源与时间窗口、统计口径、选了哪几条和为什么、外部信息的出处和发布时间、哪些画面是示意、已知限制与需要用户确认的点。

## 第一步：一次问完四件事

别分五轮问。用一条消息问完，用户答完就开工：

1. **哪个群**——给他看 `contact` 表里匹配到的群列表，让他挑
2. **哪天的记录**——默认昨天全天
3. **多长**——60 秒（约 8 条）／90 秒（约 10 条）
4. **风格**——默认 1920s 新闻片，问一句「有没有别的想法」

如果用户说「随便」「你定」，就按默认走，不要再追问。

## 执行序列

### 1. 环境

见 [references/env-windows.md](references/env-windows.md)。九个步骤，一次搭对。没搭完时所有报错都是噪音。

**通过条件**：`sh build.sh page` 出了 `index.html`，`sh build.sh stills` 出了 `stills/_sheet.jpg`。

### 2. 导数据

同一份文件的后半部分。三个断点：挑错账号库、mtime 跳过重解、WAL 代次混乱。

**通过条件**：`work/chat.txt` 首行是 `[YYYY-MM-DD HH:MM] 昵称: 内容`，条数与 `stats.md` 一致。

**拿不到当天的就退回前一天，不要回放 WAL，不要编。** 片子可以晚一天，数据不能编。

### 3. 统计

```sh
python tools/clean_chat.py work/chat.json > work/chat.txt
```

产出 `stats.md`：时间窗口、条数、人数、每小时分布、发言排行、最热 10 分钟。

**屏幕上的每个数字只能从这份文件里抄。** 口径要固定：系统消息算不算、人数怎么算，写进交付说明。

### 4. 选题

从全部消息里挑 8 条。三条标准，缺一条就换：

- **有画面**——能画成一个具体物件。打印机冒烟能，讨论产品质量不能。
- **有原话**——有一句短的、能直接引的。原话是这类片子唯一的可信度来源。
- **有反差**——荒谬、反转、起哄、深夜发疯。有观点也行，平铺直叙不行。

结构固定：头条（最长 8.4 秒）→ 5–6 个正片 → 急停（最短 3.6 秒）→ 固定栏目（天气）→ 收尾。

**选题清单必须给用户看**，附上每条的理由和引用的原话。他不点头不开工。

### 5. 文案

`parts/a_content.js` 放全部文字，`voice/lines.json` 放旁白。

旁白规则：

- 每句 12–22 字，配音 2.7–4.2 秒。超 5 秒必须拆。
- 总数 = 段数 + 8 左右。12 段配 20 句。
- 引语逐字抄，错别字和表情符号一起抄。「你麻麻」不能写成「你妈妈」。
- 旁白和画面引语牌**不要写同一句话**。同一个信息说两遍，观众会觉得被当傻子。

**每写完一版跑一次：**

```sh
python tools/check_quotes.py work/chat.txt     # 必须 ALL FOUND
```

两种模式，自动选：在 `a_content.js` 里写 `CONTENT.quotes` 登记表就是精确模式；不写则自动扫所有 `「…」` 片段，加上键名匹配 `slip(s)` / `quote*` / `note` / `text` 且含中文的字段。**推荐登记**，新加道具时不会漏。

它只保证「这段字在日志里出现过」，不保证「是这个人说的」。张冠李戴它抓不到，得你自己对着原文读一遍。

### 6. 画面

`parts/b_scenes.js`，一段一个函数。参数照 [references/case-ep01.md](references/case-ep01.md) 的段落表填。

三条构图铁律：

- 片门左右各 220px 是黑边，有效区 1480×1080，主体不能出去
- 左上角时间卡占 `{48,56,600,170}`，标题不能进
- 底部 `y > 900` 是字幕带，道具底部内容不能进

### 7. 配音 + 时间线

```sh
LIB=<工作区>/lemo sh build.sh voice      # make.py → tts → timeline，一条命令跑完
```

时间线是唯一钟表：`SECS` 定段落，`HITS` 定动作，`LINES` 定旁白，全部按**实测配音时长**排，不按字数估。

**改了文案必须重跑这一整条。** 改了字不重跑配音，卡点会全错位，而成片里不容易一眼看出来。

### 8. 静帧

```sh
LIB=<工作区>/lemo sh build.sh stills
```

出 `stills/_sheet.jpg`。打开逐帧看，四个必查项：字被切／字被压／空画面／出片门。

**这一步机器代替不了。** 本次制作八处硬伤全部在这一步发现，`readcheck` 一处都没抓到。

可疑的单张打开原尺寸看。联系表只能看清构图，看不清小字。

### 9. 渲染 → 配乐 → 合成 → 压缩

```sh
LIB=<工作区>/lemo sh build.sh video      # 约 5 分钟
LIB=<工作区>/lemo sh build.sh mix        # 默认合成音源，不需要采样库
LIB=<工作区>/lemo sh build.sh mux        # 约 15 分钟
LIB=<工作区>/lemo sh build.sh small
```

四步**不能并行**，都是吃满 CPU 的重活。

`mix` 自动选音源：`$LIB/core/audio/instruments/index.json` 存在就用真实采样，不存在就用 `audio/mix_pluck.py` 的纯 numpy 合成（不需要下载任何东西，音色薄一点但能出片）。`SYNTH=0` 强制采样，`SYNTH=1` 强制合成。

人声必须高于配乐 8–12 dB。`mux.sh` 会打印 LUFS 和峰值，偏离了它会自己警告。

## 必须停下来问用户的六个节点

下面每格右边那句话可以直接发给用户。别用「是否继续」这种问法，给具体的东西让他判断。

| 时机 | 直接发这句话 |
|---|---|
| 开工 | 「做一期新闻片，先确认四件事：① 哪个群（这几个匹配到：A / B / C）② 哪天的记录，默认昨天 ③ 多长，60 秒 8 条还是 90 秒 10 条 ④ 风格默认 1920s 新闻片，有别的想法吗」 |
| 导出后 | 「导出完成：N 条、M 个人、X 点到 Y 点。这个范围对吗？不对我重新导。」 |
| 选题后 | 「从 N 条里挑了 8 条：1…（每条一句理由 + 引用的原话）。哪条要换？没有我就按这个开工。」 |
| 事实存疑 | 「『某句』我在原始记录里搜不到，可能是我记错了或看串行了。这句是保留、改掉、还是换成另一句？」 |
| 静帧后 | 「这是 12 张关键帧（联系表见附件）。你看有没有字被切掉、被别的东西压住的？我看不出来的地方你帮我盯一下。」 |
| 交付前 | 「成片 76 秒、10 MB。配乐是 BPM 200 的 Charleston，偏闹，要不要换个轻的？确认了我就交。」 |

第三条（事实存疑）最容易漏。**你写的东西自己看着合理，不等于真发生过。** 拿不准就问，别替用户决定。

第六条的「偏闹」不是客套。配乐风格是主观的，用户听了不满意要重做整条音轨，代价比问一句大得多。

## 红线

1. 引语逐字。错别字、谐音、表情符号都照抄。脚本只能验证「这段字存在过」，验证不了「是这个人说的」。
2. 数字靠数。屏幕上每个数字能指回 `stats.md` 或某一行原文。估出来的数字最容易被抓。
3. 外部信息标来源和时间。天气写清「中央气象台 · MM-DD HH:MM 发布」。
4. 示意图标「示意」。手绘、简化、非写实的画面，角落写清楚。
5. 不碰政治、低俗、真名、电话、地址、单位。昵称可以用，但别跟现实身份关联。
6. 联系表不看，不许渲染全片。
