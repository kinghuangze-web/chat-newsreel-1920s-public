# 通用注意事项：短串场与单主持制作

这些是遇到过的故障类型及可核验的处理方法，不是每期都要执行的固定流程。按实际症状选用；不改变原有各宿主规则。

| 症状 | 容易误判的原因 | 处理与证据边界 |
|---|---|---|
| 不同栏目像换了主播 | 每段重新描述“同一种女声”，模型重新选声 | 固定身份条件；限长允许时一次连续合成。记录母带、参考 hash 和请求数；仍需听审音色一致性 |
| 只有一条音轨仍有多种声线 | 先生成不同声音再拼成一轨，或素材原声混入 | 追溯母带与请求；核对完整混音来源。单轨数量不能证明同一说话人 |
| 速度比预想快很多 | TTS 与成片各自再次加速 | 记录速度相对基准、处理阶段和总因子；统一处理后重新排字幕、动作和结尾 |
| IP 僵硬又抢画面 | 常驻大头像、三视图硬切、全部素材被挤进侧栏 | 用新闻完整画布和有目的的短串场；动作作用于身体部位，按分享尺寸判断大小与视觉主次 |
| 网格出现黑缝、暗格 | 低分辨率逐三角形缩放，或每片分别淡入淡出 | 在原尺寸离屏层绘制；适度扩展三角裁剪后整层一次合成。检查淡入中段与运动峰值。半透明画稿的重叠仍可能加深，需换合成方法或单独检查 |
| 数字与来源行“看不清” | 胶片纹理、抖动或低对比同时作用于文字 | 清晰文字最后单独画；按分享版检查。文字边界通过也不保证足够清晰 |
| 查询无报错、尾页为空，却少了半天 | 新消息分库未进入既有读取清单 | 在已授权账号范围核对实际分库、最新时间和查询结果；先确认账号及进程对应关系。修补任务内读取清单，不据此扩大读取授权；本地取尽仍不等于服务器同步完整 |
| 每条图像都指向同一缓存文件 | 导出器使用目录第一个文件或模糊路径匹配 | 按单条消息的媒体标识/摘要核对媒体索引，再对具体文件。字段随版本变化；不能硬编码某张表为通用真源。核对尺寸、内容和实际 hash |
| 图片匹配了却仍打不开 | 格式识别正确，但私有容器尚未解码 | 不把匹配成功写成可用；保留缺失状态，采用已验证替代来源或明确示意，不能用无关图顶替 |
| 高 ASR 分数却藏着错词 | 同音归一掩盖专名，强制对齐仅证明预期词能塞进时轴 | 保留原始转写、数字、词时间和置信度；专名、语气变化、低置信与插入词单独核对，最终听感另记 |
| ASR 凭空多出一句 | 静音/短停顿出现零时长低置信幻词，或提示词污染 | 查看原始词时间，独立识别有前后文的最终音轨片段，再决定是否返工。不要因一次幻词拼入另一套声音 |
| 配乐随每个停顿忽大忽小 | 瞬时语音门限控制音乐增益 | 连续旁白优先固定低电平，或按语句/段落平缓变化；核对完整音乐乐句，不能复用另一上传版本的秒数 |
| 新一期验收报告找不到文件 | 复用旧片名的 glob，空列表仍被当作成功 | 明确预期输出文件名、数量和非空；从实际文件生成清单。名称相似、旧报告 PASS 都不能替代当前 hash |
| 生成脚本重跑后退回旧布局 | 手改 HTML 后生成器未同步，源头不明 | 标出本期可编辑真源；需要重生成时同步修正生成器或只保留一条可信构建路径。历史脚本不能伪称可无损重建最终工程 |
| 修改声音后报告还沿用旧 PASS | 时间线、字幕、取样和音轨已变，证据未更新 | 按变化范围废止相关报告；只有对象 hash、相关源与环境仍适用时复用本次证据。分别核验两种分辨率实际音轨 |
| “分享了复刻资料”被说成“已验证一键运行” | README 存在就升级为运行成功 | 区分资料核对、可运行接口、实际复现；界面开放邀请也不等于功能全测通过 |

发布方法包时只收录通用规则、必要代码和虚构输入；原始群聊、账号标识、路径、媒体索引、参考音频与成片留在本地。已有仓库有多个宿主时，把新风格放进明确独立目录，比较基线树确认原文件未改动，不用新经验覆盖别人版本的默认。
